## 计费模型

- 计费单位是**额度**（以美元折算）：按调用模型的输入 / 输出 token 数 × 模型单价计算。
- 每次调用先扣 **密钥配额**，再扣 **账户余额**；密钥设置了配额时，两者都不能超。
- 密钥若设置了分组，按该分组的计费倍率结算。

## 控制台里看什么

| 页面 | 用途 |
| --- | --- |
| **数据看板** | 请求量、消费趋势、各模型用量占比 |
| **钱包** | 查看账户余额；通过 **充值** 或在 **兑换码** 页兑换额度 |
| **使用日志** | 每次调用的模型、输入 / 输出 token 数、费用、耗时、状态与失败原因 |
| **模型广场 / 模型定价** | 每个模型的单价（通常为每百万 token 的输入 / 输出价格）与可用性 |

排查一次异常调用：打开 **使用日志**，按时间或模型过滤，查看该请求的状态与耗时；失败请求会给出失败原因。

## 用 API 查额度

```bash
# 密钥对应的总额度（hard_limit_usd，美元）
curl --fail-with-body https://th.3cool.cc/v1/dashboard/billing/subscription \
  -H "Authorization: Bearer ${JIZHI_API_KEY}"

# 已用额度（total_usage，单位为美分，除以 100 即美元）
curl --fail-with-body "https://th.3cool.cc/v1/dashboard/billing/usage" \
  -H "Authorization: Bearer ${JIZHI_API_KEY}"
```

`subscription` 返回剩余与已用额度之和；具体统计的是密钥自身还是整个账户，取决于站点设置。金额单位跟随站点展示设置（默认按美元折算，也可能配置为人民币或直接以 token 数展示）。

## 额度用尽会怎样

调用会返回余额不足错误（见[第 5 章](../05-faq/)）。处理方式：在 **钱包** 充值，或使用 **兑换码** 兑换额度；若密钥设置了单独配额上限，还需要在「API 密钥」页调大该密钥的配额或改为无限配额。
